# BQ79616 断线诊断分析：如何让 OW 先于 OV/UV 报出

> 2026-09-05，Wonder 提出，Simon 整理。
> 场景：断线是采样回路阻抗由小变大的渐变过程，OV/UV（实时硬件 protector）总是先动作，断线往往报不出来。

## 机理：为什么 OV/UV 先报

断线后电流源/沉泄放 Cvc 滤波电容：

- 本通道读数缓降 → 触发 **CUV**
- 上方邻通道读数等比上升 → 触发 **COV**

OV/UV 是持续运行的硬件比较器；OW 是 host 主动轮询的诊断。渐变过程中 protector 必然先触发。
（SDAA369 以 BQ76952 为例说明同一机理；BQ769x2 甚至没有专用 OW 位。）

## 两代芯片机制对比

| | BQ79616 | BQ79718 |
|---|---|---|
| 方式 | 主动式：host 发起电流沉 + 阈值比较 | 被动式：恒流常开 + host 合理性检查 |
| 阈值 | OW_THR[3:0]：500mV~5V，300mV 步进 | 无（判据在 host 软件） |
| 结果 | FAULT_COMP_VCOW1/2 / CBOW1/2 | 无专用 OW 位 |

## 616 的三条解法（可叠加）

### ① 调高 OW_THR（核心）

渐变断线 = 回路阻抗 R 增大。OW 检查时电流沉 I_sink 叠加，读数分压比正常测量更狠：

- 正常测量跌破 UV 阈值需要较大的 R
- OW 检查跌破 OW_THR 需要的 R 小得多 → **同一渐变过程中 OW 判据先满足**

OW_THR 取值：保证 < 最低正常 cell 电压（防误报）的前提下尽量高，灵敏度最高。

### ② 缩短 OW 轮询周期

诊断可随时反复执行（E2E 确认 BIST/诊断不限启动时刻）：

```
DIAG_COMP_CTRL3[OW_SNK1:0]=01 开 VC 电流沉
→ 等 dV/dt（I_sink 对 Cvc 放电到阈值）
→ COMP_ADC_SEL=010，COMP_ADC_GO=1
→ 等 DRDY_VCOW → 读 FAULT_COMP_VCOW1/2 → 关电流沉
```

塞进主循环周期执行，断线后一轮内报 OW。注意：检查期间电流沉会扰动读数，避开均衡/保护判定窗口。

### ③ host 端仲裁 + VBAT/ΣVCELL 交叉校验

- OV/UV 触发时 host 先跑一轮 OW 检查再上报，是 OW 就归类为断线
- **VBAT vs ΣVCELL 比对**（SDAA369 方法）：断线通道使 ΣVCELL 偏离 VBAT，差值 ≈ 失联通道电压 → 区分真低压与断线
